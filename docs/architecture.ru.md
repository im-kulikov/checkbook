# Как устроен Чекбук

[English version](architecture.md)

Чекбук — статическое прогрессивное веб-приложение. Всё важное происходит на телефоне: распознавание чеков, подсчёт
итогов, очередь изменений. GitHub только хранит файлы; поставщик ИИ видит чек, только когда человек нажал «Уточнить
с ИИ», и только через шлюз, который семья разворачивает сама.

## Из чего состоит

| Часть | Где работает | Что делает |
|---|---|---|
| Приложение (PWA) | браузер телефона, установлено на экран «Домой» | интерфейс, распознавание, итоги, офлайн-кэш и очередь отправки |
| Хостинг | GitHub Pages | отдаёт собранное приложение; данных семьи не видит |
| Репозиторий данных | приватный репозиторий GitHub, принадлежит семье | JSON-файлы операций, категорий и получателей; файлы чеков |
| ИИ-шлюз (по желанию) | небольшой контейнер на собственном сервере семьи | проверяет, что запрос пришёл от того, кто может открыть репозиторий данных, и вызывает поставщика ИИ ключом с сервера |

## Данные

Одна операция — один JSON-файл; один чек — один файл, названный по хэшу содержимого. Двое почти никогда не правят
один и тот же файл, а повторно загруженный чек хранится один раз.

```
meta/workspace.json           базовая валюта, участники, версия схемы
meta/categories.json          дерево категорий: id -> узел
payees/<payeeId>.json         получатель: имя, ИНН, алиасы, категория по умолчанию
tx/2026/10/<ULID>.json        операция; папка — месяц создания ULID, не меняется
files/ab/<sha256>.pdf         исходный файл чека; «ab» — первые два символа хэша
README.md                     как прочитать данные без приложения
```

Деньги хранятся целыми копейками; даты — локальным временем плюс часовой пояс IANA.

## Доступ без учётных записей

Логинов и паролей нет. Устройство «вошло», когда на нём лежит fine-grained ключ GitHub, открывающий репозиторий данных
(Contents: чтение и запись, Metadata: чтение). Владелец учёта выпускает ключ в мастере настройки. Участник получает
зашифрованное приглашение QR-кодом (`checkbook:1:<base64>`, AES-GCM) и 12-значный код, который говорят вслух, —
фотография одного QR бесполезна. У каждого устройства свой ключ, владелец может отозвать его в любой момент.

Ключ лежит только в IndexedDB устройства: никогда в адресе, журналах, сообщениях об ошибках и экспорте. Необязательная
блокировка (Face ID или отпечаток через WebAuthn либо PIN) защищает интерфейс от посторонних.

## Синхронизация

- **Запись.** Изменения идут через Git Data API: один коммит на пакет до 20 операций, файлы чеков — отдельными blob.
  Ветка двигается только вперёд; при гонке приложение переносит свой пакет поверх и повторяет.
- **Чтение.** Приложение опрашивает голову ветки с ETag, поэтому неизменившийся репозиторий не тратит лимит. Запросы
  идут с `cache: 'no-store'`, чтобы браузер не отдал устаревшую голову.
- **Без сети.** Всё кэшируется в IndexedDB. Новые и изменённые операции ждут в очереди и уходят в порядке создания,
  как только появится сеть. Создание и удаление операции до отправки взаимно отменяются.
- **Конфликты.** Отдельный файл на операцию делает настоящие конфликты редкими; если двое изменили одну операцию,
  приложение покажет обе версии и даст выбрать.

## Распознавание

Сначала бесплатные и точные источники, ИИ — последним:

1. **QR кассового чека** (камера или картинка): дата, время, сумма и фискальные признаки.
2. **Текст PDF**: шаблоны квитанций о переводах и оплатах популярных банков.
3. **OCR** (Tesseract.js) для фото и скриншотов, с отметкой уверенности у каждого поля.
4. **ИИ (по желанию, по кнопке)** через шлюз. Каждое значение приходит с дословной цитатой из документа, и приложение
   сверяет его с суммой из QR и правилами шаблона, прежде чем предложить.

Тяжёлая работа идёт в воркерах (pdf.js, Tesseract.js, zxing-wasm), поэтому интерфейс не тормозит даже на старых iPhone.

## Обновления и первый запуск

Service worker кэширует оболочку приложения. Когда выходит новая версия, приложение пишет «доступна новая версия» и
переключается при следующем запуске или по нажатию; данные, записанные более новой версией, старая не откроет.
Первому запуску после установки нужна сеть; после уведомления «Готово к работе без сети» приложение открывается и без неё.

## Безопасность

- Ключей ИИ нет нигде, кроме окружения шлюза; секретов нет ни в репозитории, ни в сборке.
- Строгая Content Security Policy: `connect-src` разрешает только само приложение, `api.github.com` и заданный шлюз.
- Никаких `innerHTML` и `eval`; текст пользователя всегда выводится как текст.
- CI проверяет каждый коммит на секреты (gitleaks) и гоняет unit- и end-to-end-тесты в Chromium и WebKit iPhone.
